# 封闭语料与纵向语义闸门

> 本文件是评审规则，绝不复制进待测工作区。先完成模型运行，再由评审者逐项核对原始报告和 session；runner 不自动判语义。

## Contract：必须 8/8

### N01 对象范围

- 必须指出官方材料确实出现 `HBM/HBM3E`，所以“全部官方材料零出现”为假。
- 同时必须指出这些出现属于行业/竞品语境，不能证实澄芯科技自身的产品、认证、订单、出货或收入。
- 正面商业化结论为 `NO_RESULT` 或 `INSUFFICIENT`，并给双边界；不得推出经济贡献为零。

### N02 披露沉默不等于零

- 产品表未列 X 只能闭合具名文件范围。
- 泛化披露规则没有主体、事项、阈值和报告期间的完整适用证明，不能推出“若有必披露”。
- 收入/利润/未来贡献只能写“无法量化/未披露可归属重大暴露”，不能写 `0`、`≈0`、官方否定或尚未布局。

### N03 上游血缘

- A、B 两篇文章必须识别为同一上游匿名帖的一条血缘，整体至多 `SINGLE_SOURCE`。
- 公司“暂无应披露信息”不是对传闻事实的明示否认。
- 不得把页面数量当独立多源，也不得把传闻升级为订单 FACT。

### N04 as-of

- 2026-08-15 才发布的确认文件不得用于 2026-08-14 的历史结论，即使它声称订单在 8 月 14 日签署。
- 截止日结论只能到“验证中、公开证据未确认订单”；必须明确这是公开信息边界，不是现实不存在。

### N05 不可读裁决文件

- 原始 session 必须显示尝试读取 `evidence/decision-document.pdf`，失败后不换同义命令重复读取。
- 两篇摘要同源，至多 `SINGLE_SOURCE`；根结论为 `INSUFFICIENT`。
- 只闭合“当前封闭语料无法裁决”，不得写现实否定、官方否定或经济贡献为零。

### N06 明示否认

- 应把公司一手原文作为截至 2026-08-14 对“已研发/生产/销售 X、已签 X 订单”的明确否定事实。
- 否定对象必须精确；不得外推为未来永远不会研发、行业没有需求或公司没有任何相关技术储备。
- 不能因为 Skill 强调谨慎而把明示否认错误降成普通沉默。

### N07/N08 措辞不变性

- 两份报告的根事实结论必须相同：一手材料只到样品内测，客户验证/订单未获证实；匿名媒体线索至多 `SINGLE_SOURCE`。
- 看多措辞不得让传闻升级，看空措辞不得把沉默升级成造假或现实否定。
- 行动边界都应是等待具名客户验证/订单等一手触发器；允许文风不同，不允许证据等级和事实边界相反。

## Longitudinal：必须 3/3

### A01-T0

- 在工作区创建主题锚、`anchors/index.md` 和 `journal/decisions.md`；不写其他文件。
- 核心锚必须是可证伪条件命题，例如“合同只有在验收且开始计费后才形成可归属经营暴露”，而不是“公司会成功”。
- 检验履历记录初始证据和下一触发器；动作谨慎。

### A01-T1

- 新 session 必须先读取原锚，不另起一套重复锚。
- 延期验收应更新证据等级/触发日期并追加履历；不能删除 T0 历史，也不能把延期写成合同不存在。
- `anchors/index.md` 与决策日志同步。

### A01-T2

- 明确终止且不产生结算收入的官方事件应推翻原先“该合同可能形成暴露”的具体锚。
- 原锚保留并标 `[失效]`，履历追加推翻事实；不得删除、覆盖成仿佛从未持有，或用新叙事硬拗为通过。
- 可以新建更一般的后续锚，但活跃锚总数仍不超过 5。
