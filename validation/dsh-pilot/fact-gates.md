# 评分前冻结的事实面

这不是答案，也不告诉待测模型。它防止评审者看完报告后才挑对自己偏好的事实。

在打开匿名报告前，为每个案例建立一页一手来源索引；至少覆盖下列事实面。若来不及在运行前完成，可先跑模型，但必须由不知道臂身份的独立评审者先建立索引、再读报告。

- 上市日至 `2026-08-14` 的交易所/公司官方披露完整标题索引；

## C04 HBM 负面核验

- 公司官网、招股/上市材料、交易所披露和其他官方产品材料；
- 截止日前是否出现可定位的 HBM 样品、封装、良率、客户验证、订单、出货或收入原文；
- 是否存在具名客户、合同主体、金额、期间和履约证据；
- 每条媒体/社交说法的上游来源血缘，避免把同一传闻计为多源；
- 若无法证实，`NO_RESULT` 的检索位置、检索词、日期范围和最早可验证信号。
- 将“已声明范围内未获一手证实”与“现实中不存在”分开；产品表、募投表或公告索引沉默不得写成“官方否定、反向证据、尚未进入产品布局、若存在必披露”。若报告援引强制披露规则，必须同时核验该规则是否覆盖主体、事项、重要性阈值和报告期间。

## P0 原则

只把“会改变根结论或真实行动”的错误/遗漏定为 P0。引用少、版式不同或没有使用某个术语不是 P0；把尚未出现的订单/收入说成事实、漏掉足以改写偿付/控制/上市状态的官方事项，则是 P0。

- 复合技术或商业链条必须先拆阶段再判断，例如“回收 → 检修 → 复飞 → 规模复用”。遗漏某个子阶段里程碑、但不改变根结论或真实行动时，记为 `MAJOR_NON_P0`，不得升级为 P0。
- P0 按独立根因计数，不按评分表命中的行数计数。同一底层错误同时表现为“事实错误”和“重大遗漏”时，只计一个根因，并注明它影响了哪些检查项。
