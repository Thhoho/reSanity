# DSH 薄壳兼容测试提示

先使用 `skill` 工具显式加载 `resanity`，确认加载成功后再继续。不要读取其他研究 Skill、旧报告、锚库或验证结果。

请以 `2026-08-14` 为截止日，核验：仅凭截至该日的公开一手材料，能否证实长鑫存储已经实现 HBM 规模量产，并获得具名头部客户的商业订单？若不能，给出有边界的 `NO_RESULT`、证据缺口和最早可验证信号；不得用媒体转述、产业链传闻或“技术上可能”补齐事实。凡由未披露支持的结论，必须紧邻写出 `检索结论：...` 与 `现实边界：这不证明现实中不存在未公开、未达到披露门槛或发生在报告期外的活动。`，不得写成官方否定。

这次不是 A/B 语义评分，而是正式报告机械兼容测试。请在当前工作目录完成：

1. 保存唯一语义报告为 `report.md`，含明确 as-of、`[C#]` 主张标记和 `[E#]` 证据标记；
2. 保存 `report.receipt.json`，schema 为 `resanity.audit-receipt.v1`，内容与实际文件、Skill hash、预算上限和来源索引一致；`runtime` 只写已知的 host/model，预算各项只写 `limit`，不得填写 `used`、token、工具次数或耗时；
3. 允许保存 `sources/` 快照，但本次从 `artifacts` 中省略 `host_receipt`，也不创建或伪造 `resanity.host-receipt.v1`；它只能由宿主在会话结束后从原始会话生成；
4. 使用该 Skill 随包的 `tools/research_check.py` 对回执执行**一次非 strict 检查**；
5. 把第一次检查的完整 stdout 和退出码保存为 `checker-first-result.txt`；
6. 无论通过或失败都立即停止。失败后不得重搜、补证据、改写报告或再次运行检查器。

最终回答只列出生成文件、第一次检查结果和任何明确的 DSH 兼容限制。`AUDIT_RECEIPT_OK` 只代表机械闭合，不代表研究正确。
